# Строгая проверка полей в блоке «Personalisierung»

Касается всех страниц товаров: блок персонализации у всех товаров общий.

## Поле «Datum (optional)»
- Поле ввода с иконкой календаря. По клику открывается календарь (с выбором месяца и года), можно вводить дату и вручную.
- Принимаются только цифры, точки подставляются сами: 24062026 → 24.06.2026. Буквы и другие символы не вводятся.
- Дата проверяется на существование (31.02 не пройдёт, високосные годы учитываются), допустимы даты с 01.01.1900 по 31.12.2100, прошлые разрешены.
- Пустое поле допустимо. Ошибка: «Bitte geben Sie ein gültiges Datum ein (TT.MM.JJJJ)» / EN-вариант.
- В корзину, заказ и админку дата всегда уходит как TT.MM.JJJJ.

## Поле «Name(n)»
- Обязательное, 2–50 символов, счётчик «0/50».
- Разрешены буквы любых алфавитов, пробел, «-», «'», «&», «+». Цифры и спецсимволы запрещены.
- Пробелы по краям обрезаются, двойные пробелы сжимаются.
- Ошибки: «Bitte geben Sie mindestens 2 Zeichen ein», «Nur Buchstaben, Leerzeichen und - & + sind erlaubt» (+ EN).
- Сейчас имя обязательно только у части товаров; теперь станет обязательным у всех.

## Поле «Wunschtext (optional)»
- До 150 символов, счётчик «0/150», не больше 3 переносов строки.
- Разрешены буквы, цифры, пробелы и знаки . , ! ? : ; - ' " & ( ) ❤.
- HTML-теги удаляются; ссылки (http, www, .com и т. п.) и 4+ одинаковых символа подряд запрещены.
- Ошибка: «Der Text enthält nicht erlaubte Zeichen» (+ EN).

## Поведение
- Проверка срабатывает, когда пользователь уходит из поля, и при нажатии «In den Warenkorb».
- Ошибка показывается красным текстом под полем, рамка поля краснеет.
- Пока есть ошибки, товар не добавляется: страница прокручивается к первому полю с ошибкой и ставит на него курсор.
- Те же правила повторно проверяются на сервере при оформлении заказа; некорректный заказ отклоняется с понятной ошибкой.
- Размер, рамка, мотив, цена и корзина не меняются; стиль сайта остаётся прежним.

## Технические детали
- `src/lib/personalization-schema.ts` (общий для браузера и сервера): Zod-схема `personalizationSchema` (names/date/message), функции `sanitizeName`, `sanitizeMessage` (удаление тегов, `< >`), `maskDate`, `isValidDate`, `parseDE/formatDE`. Ошибки — ключи переводов (`pers.errors.*`).
- `src/components/product/personalization-fields.tsx`: React Hook Form (`mode: "onBlur"`, zodResolver) с компонентами Input/Textarea/Label, Popover + Calendar (`captionLayout="dropdown"`, fromYear 1900, toYear 2100, `pointer-events-auto`), aria-invalid/aria-describedby; через ref отдаёт `validate()` → валидные значения или фокус на первом ошибочном поле (`setFocus` + `scrollIntoView`).
- `src/routes/product.$id.tsx`: заменить три текущих поля на компонент; `onAdd` вызывает `await validate()` перед существующими проверками размера/мотива; удалить старую проверку `errors.pers`. Остальная логика без изменений.
- Сервер: в `src/lib/checkout-schema.ts` для `personalization` добавить `superRefine`, проверяющий `names`/`date`/`message` той же схемой (names обязателен при наличии ключа), так что `payments.functions.ts` отклонит неверные данные до создания заказа.
- Установить `@hookform/resolvers`, если его нет. Переводы в `src/i18n/de.ts` и `en.ts` (`pers.*`).
